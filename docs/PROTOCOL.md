# LanAudioStream 局域网音频串流协议（LAS1 v1.0）

本文档描述桌面端（Windows 11，发送方）与手机端（Android，接收方）之间的私有协议。
协议只依赖 UDP，全部字段小端序（little-endian），面向低延迟局域网场景设计。

---

## 1. 总览

| 项目 | 取值 |
|---|---|
| 传输层 | UDP（无连接、无序、无重传） |
| 发现端口 | **47654/UDP**（广播 + 单播） |
| 音频数据端口 | **47655/UDP**（可在桌面端修改） |
| 音频编码 | Opus，48 kHz，立体声，5/10/20 ms 帧 |
| 码率 | 64 / 96 / 128 / 160 / 192 / 256 / 320 kbps（VBR） |
| 抗丢包 | in-band FEC（≥10 ms 帧）+ 同包重发上一帧（可选，默认开） |
| 时钟同步 | NTP 风格四时间戳交换（RTT/2 偏移估计） |
| 保活/统计 | 手机端每 100 ms 回传 Receiver Report，桌面端超过「断连超时」（默认 8 s）无回传时只暂停发送、保留会话 |
| 包头 | 固定 24 字节 |

典型的一次会话：

```
手机                                       桌面端
 |--- PROBE (广播 255.255.255.255:47654) --->|
 |<-- ANNOUNCE (单播, 含名称/端口/状态) ------|
 |--- HELLO (至 47655) --------------------->|
 |<-- HELLO_ACK (编码参数) ------------------|
 |--- START -------------------------------->|   桌面端开始推送 DATA
 |<== DATA (Opus 帧, 每帧一个报文) ==========|
 |--- RR (每 100ms, 丢包/抖动/延迟) -------->|
 |--- SYNC_REQ / <-- SYNC_RSP ---------------|   估计时钟偏移 -> 端到端延迟
 |--- BYE ---------------------------------->|   任一方可主动结束
```

---

## 2. 报文结构

### 2.1 公共头（24 字节）

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | magic | ASCII `LAS1` |
| 4 | 1 | version | 协议版本，当前 `1` |
| 5 | 1 | type | 报文类型，见下表 |
| 6 | 2 | flags | 位标志，`bit0` = 携带冗余负载 |
| 8 | 4 | seq | 音频帧序号（每帧 +1，会话开始时归零）；仅 DATA 有效 |
| 12 | 8 | captureUs | 该帧**首采样点**的采集时刻（发送方单调时钟，微秒） |
| 20 | 2 | payloadLen | 主负载长度 |
| 22 | 2 | redLen | 冗余负载长度（0 表示无） |

其后紧跟 `payloadLen` 字节主负载，再跟 `redLen` 字节冗余负载。

### 2.2 报文类型

| 值 | 名称 | 方向 | 说明 |
|---:|---|---|---|
| 1 | DATA | 桌面 → 手机 | 一帧 Opus |
| 2 | HELLO | 手机 → 桌面 | 请求建立会话 |
| 3 | HELLO_ACK | 桌面 → 手机 | 回传编码参数（会话中可重发以热更新参数） |
| 4 | START | 手机 → 桌面 | 请求开始推送音频 |
| 5 | BYE | 双向 | 主动结束会话 |
| 6 | PROBE | 手机 → 广播 | 发现请求 |
| 7 | ANNOUNCE | 桌面 → 广播/单播 | 发现响应 |
| 8 | SYNC_REQ | 手机 → 桌面 | 时钟同步请求 |
| 9 | SYNC_RSP | 桌面 → 手机 | 时钟同步响应 |
| 10 | RR | 手机 → 桌面 | 接收统计报告（同时作为保活） |
| 11 | SETTINGS | 双向 | 音频设置：手机下发改动，桌面回推权威状态（见 §2.9） |

### 2.3 DATA（type=1）

- `payloadLen`：当前 Opus 包的字节数。
- `flags.bit1`（`FlagSilence`）置位且 `payloadLen=0` 时表示**该序号是 DTX 静音**：发送端在静音段只发少量这种 24 字节包头包，接收端按序号把缺的帧补成静音，**不计丢包、不计欠载**。
- `flags.bit0` 置位时，报文尾部附加 **上一帧（seq-1）** 的完整 Opus 包（`redLen` 为其长度）。
  接收端在检测到 `seq-1` 缺失时可直接用其恢复，等价于“零重传的 1 级冗余”。
- 若接收端已经收到 `seq-1`，应丢弃冗余段。

### 2.4 ANNOUNCE（type=7）负载

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | version |
| 1 | 1 | reserved |
| 2 | 2 | streamPort（桌面端音频端口） |
| 4 | 2 | flags（`bit0` = 正在串流） |
| 6 | 2 | nameLen |
| 8 | nameLen | name（UTF-8，如 `LanAudioStream@DESKTOP-01`） |

桌面端默认每 1 s 向 `255.255.255.255:47654` 及各网卡子网广播地址发送一次，并在收到 `PROBE`
时立即单播回应。

**探测节能约定：**
- 桌面端在**已有客户端处于串流状态**时停止周期广播（仍会响应对方主动发来的 `PROBE`）。
- 手机端在**会话建立后**停止发送 `PROBE`，断开连接后自动恢复每秒探测。
- 实测：一次 16 s 的会话中，桌面端只在前 1.5 s 收到 3 个探测包，之后为 0。

### 2.5 HELLO（type=2）负载

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | version |
| 1 | 1 | reserved |
| 2 | 4 | nonce |
| 6 | 4 | desiredBitrateBps（0 = 由桌面端决定） |

### 2.6 HELLO_ACK（type=3）负载

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | codec | 1 = Opus |
| 1 | 1 | channels | 2 |
| 2 | 1 | frameMs | 5 / 10 / 20 / 40（PCM 无损 ≤ 10） |
| 3 | 1 | redundancy | 1 = 开启帧冗余 |
| 4 | 4 | sampleRate | 48000 |
| 8 | 2 | frameSamples | 每声道采样数（48000×frameMs/1000） |
| 10 | 4 | bitrateBps | 目标码率 |
| 14 | 4 | sessionId | 会话标识 |

会话进行中桌面端修改参数后，会重新发送 HELLO_ACK；手机端据此重建解码器与输出缓冲。

### 2.7 SYNC_REQ / SYNC_RSP（type=8/9）

- `SYNC_REQ`：8 字节 `t1`（手机单调时钟，微秒）。
- `SYNC_RSP`：24 字节 `t1`（回显）、`t2`（桌面端收到时刻）、`t3`（桌面端发送时刻）。

手机端计算：

```
rtt    = (t4 - t1) - (t3 - t2)
offset = ((t2 - t1) + (t3 - t4)) / 2      // offset = 桌面时钟 - 手机时钟
```

取 **最小 RTT** 样本作为最终偏移（避免排队抖动污染），随后：

```
端到端延迟 ≈ 手机播放时刻(本机时钟) + 输出缓冲 - (captureUs - offset)
```

### 2.8 RR 接收报告（type=10，56 字节）

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | seqMax | 已接收的最大序号 |
| 4 | 4 | recv | 成功接收报文数 |
| 8 | 4 | lost | 未恢复的丢帧数 |
| 12 | 4 | late | 过晚到达被丢弃的帧数 |
| 16 | 4 | dup | 重复报文数 |
| 20 | 4 | jitterUs | RFC3550 式抖动估计（微秒） |
| 24 | 4 | e2eLatencyUs | 端到端延迟（微秒，`0xFFFFFFFF` 表示未知） |
| 28 | 4 | bufferUs | 抖动缓冲深度（微秒） |
| 32 | 4 | recvBitrateBps | 接收码率 |
| 36 | 4 | plcFrames | 丢帧补偿次数 |
| 40 | 4 | underruns | 播放欠载次数 |
| 44 | 2 | lossPermille | 丢包率千分比（‰，÷10 即百分比） |
| 46 | 1 | reserved | 保留（低延迟模式已取消，恒为 0） |
| 47 | 1 | reserved | 保留 |
| 48 | 4 | targetBufferUs | 当前自适应目标缓冲（微秒） |
| 52 | 1 | reserved | 保留（播放音量功能已移除，恒为 0） |
| 53 | 1 | autoReconnect | 1 = 开启断线自动重连 |
| 54 | 2 | reserved | 保留 |

> 说明：桌面端不再显示这些回传指标（运行状态只显示本机可得的数据），RR 仍每 100 ms 发送，
> 用于保活与「按 key 16 断连超时（默认 8 s）判定客户端无响应 → 只暂停发送、保留会话」；手机端自身的延迟/抖动/缓冲等指标仍在本机显示。


### 2.9 SETTINGS（type=11）负载 —— 手机端远程设置

两端**都只在用户点击「保存设置」时**发送一次 SETTINGS（取消实时同步）；接收方校验并应用后，
**用同一条消息回推完整权威状态**，发送方据此刷新界面。连接建立（START）时桌面端也会推一次，
用于把手机界面初始化成电脑端的真实配置。负载为紧凑 TLV：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | count（最多 32 项） |
| 1 + 5×i | 1 | key |
| 2 + 5×i | 4 | value（小端 u32） |

**键值表：**

| key | 名称 | 取值 | 方向 | 说明 |
|---:|---|---|---|---|
| 1 | 编码码率 | 32–320（kbps） | 手机→桌面 | Opus 目标码率，VBR |
| 2 | 帧长 | 5 / 10 / 20 / 40（ms） | 手机→桌面 | 越短延迟越低、丢包越敏感 |
| 3 | 抗丢包冗余 | 0/1 | 手机→桌面 | 每包附加上一帧，带宽约翻倍 |
| 4 | 采集缓冲 | 10 / 20 / 30 / 50（ms） | 手机→桌面 | 改动会重建采集源（短暂中断） |
| 5 | 静音电脑扬声器 | 0/1 | 手机→桌面 | 静音后仍继续采集与串流 |
| 6 | 声道 | 1 / 2 | 手机→桌面 | 单声道在桌面端下混，省一半带宽 |
| 7 | DTX | 0/1 | 手机→桌面 | 静音时几乎不发包 |
| 8 | 编码复杂度 | 1–10 | 保留 | 当前固定为 10 |
| 9 | 抖动缓冲策略 | 0 自动 / 1 延迟优先 / 2 稳定优先 | 双向 | 改动立即在本机生效，并随「保存设置」同步给另一端 |
| 10 | 播放音量 | — | **已废弃** | 播放音量功能已移除，键位保留不再使用（收到即忽略） |
| 11 | 低延迟模式 | — | **已废弃** | 低延迟模式已取消，键位保留不再使用（收到即忽略） |
| 12 | 断线自动重连 | 0/1 | 双向 | 改动立即在本机生效，并随「保存设置」同步给另一端 |
| 13 | 音频格式 | 1 = Opus / 2 = PCM16 | 双向 | PCM 为无损直传（48kHz 立体声约 1.5 Mbps），自动关闭冗余、帧长上限 10 ms |
| 14 | 采样率 | 8000–48000（Hz） | 双向 | Opus 支持 8/12/16/24/48k；桌面端在 48k 采集后重采样 |
| 15 | 开发者模式 | — | **已移除** | 功能已删除，键位保留不再使用（收到即忽略） |
| 16 | 断连超时 | 1–600（秒） | 双向 | 桌面端「客户端无响应」阈值与手机端重连阈值共用 |
| 17 | 指标刷新率 | 1–60（Hz） | 手机本地 | 界面文本/曲线/电平条刷新率；桌面端忽略该键 |
| 18 | 通知栏指标 | 0/1 | 手机本地 | 是否在通知栏刷新实时指标；桌面端忽略该键 |

**时序约定：**

1. 手机收到 `HELLO_ACK` 后 `START`；桌面端在 `START` 时推送一次完整状态（key 1–7、9、12–14、16），手机据此初始化界面。
2. 用户点「保存设置」→ 该端发送**包含全部待同步项的一条** SETTINGS。
3. 接收端校验范围 → 应用（仅在参数真正变化时重建编码/采集管线）→ 重发 `HELLO_ACK`（编码参数变化时）→ 回推完整状态。
4. 发送端以回推的状态为准刷新界面（不做乐观更新）；回推只回填「值确实不同」的控件，避免误触发。
5. 「重置所有设置」只重置本端界面与默认值，不发送任何报文；用户再点「保存设置」才同步给另一端。
6. 未知 key 必须忽略；数值越界时接收端夹取到合法范围（例如 PCM 帧长夹到 10 ms）。

## 3. 会话状态机

**桌面端：**

```
Idle ──HELLO──> Hello ──START──> Streaming ──BYE / 按 key 16 超时（默认 8s 无 RR，只暂停发送）──> Idle / 保留会话
```

- 收到 `HELLO` 即记录手机地址（UDP 源地址），并回复 `HELLO_ACK`。
- 收到 `START` 后：编码器复位、`seq = 0`、开始发送 `DATA`。
- 按「断连超时」（key 16，默认 8 s）检查 `RR` 是否超时；超时**只暂停发送**，保留会话与客户端，收到 RR 或新的 START 立即恢复发送（不再把会话打回 Idle）。
- 停止串流或退出时向手机单播 `BYE` 并恢复本机扬声器状态。

**手机端：**

```
Idle ──PROBE/ANNOUNCE──> Found ──HELLO/HELLO_ACK──> Handshaked ──START──> Playing
                                              ↑                             │
                                              └──── 3s 无 DATA / BYE ───────┘
```

重连采用指数退避（300 ms → 4 s），发现到多个桌面端时优先选择“正在串流”的目标。

## 4. 时序与延迟预算

| 环节 | 典型值（本机实测） |
|---|---|
| WASAPI Loopback 采集缓冲 | 10–20 ms |
| Opus 帧长 + 编码 | 5–10 ms（编码 <0.5 ms） |
| 局域网传输 | 0.2–3 ms |
| 抖动缓冲（自适应目标） | 40–400 ms（冷启动约 60 ms；实测干净链路稳定在 30–60 ms） |
| AudioTrack 输出缓冲 | 约 80 ms |
| **合计端到端** | **约 130–200 ms（稳定局域网典型值）** |

实测（Windows 11 + 千兆局域网 + 本机回环）：桌面端采集→手机解码 **≈20 ms**（不含本地扬声器播放缓冲），
丢包 0%，抖动 <0.2 ms。

---

## 5. 版本与兼容性

- 版本号位于头部 `version` 字段，接收方遇到不认识的版本应直接丢弃报文。
- 新增字段必须追加在负载尾部；`HELLO_ACK` 允许尾部扩展（接收方按 `payloadLen` 判断）。
- 未知 `type` 必须静默忽略（向前兼容）。
